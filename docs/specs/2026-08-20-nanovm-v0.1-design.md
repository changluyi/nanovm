# nanovm v0.1 设计文档 — Hello VM

> 目标：一个零依赖（仅 libc）的 KVM microVM 教学实现，对标 Firecracker 的最小子集。
> 定位：开源社区项目，卖点是"小到一天能读完"。

## 验收标准

`cargo run --release` → 终端打印 `hello from nanovm` → 进程干净退出（退出码 0）。
release 二进制 < 1MB，依赖数 = 1（libc）。

## 架构（4 文件，~400 行）

```
src/
├── main.rs    装配：open KVM → 建 VM → 映射 guest 内存 → 加载 guest → 跑 vCPU
├── kvm.rs     /dev/kvm 裸 ioctl 封装（常量手写，与 linux/kvm.h 对齐）
├── loader.rs  实模式汇编 guest，内嵌字节码
└── vcpu.rs    KVM_RUN 循环 + exit 分发
```

## 关键技术决策

1. **guest 是 16 位实模式汇编**（非 Linux 内核）：往 COM1（端口 0x3f8）逐字符 `out`，
   最后 `hlt`。端口 IO 会产生 `KVM_EXIT_IO`，VMM 直接把数据打到 stdout —— 无需模拟 UART 芯片。
2. **复位向量技巧**：CPU 复位后从 0xFFFF_FFF0 取指。在该地址放一条
   `ljmp 0x0000:0x0000`（EA 00 00 00 00），跳到物理 0 处的 guest 代码 —— 无需 KVM_SET_SREGS。
3. **内存布局**：两个 4KB 区域 —— slot0 映射到 guest 物理地址 0（代码），slot1 映射到
   0xFFFF_F000（复位跳转页）。均用 mmap 匿名分配保证页对齐。
4. **kvm_run 结构体按 uapi 头文件偏移读取**（exit_reason@8, io.direction@32, port@34,
   count@36, data_offset@40），避免复制整个可变长结构。

## vCPU 主循环

```
loop {
    ioctl(KVM_RUN)
    match exit_reason {
        KVM_EXIT_IO(2)  => direction==OUT && port==0x3f8 → 打印 data
        KVM_EXIT_HLT(5) => 干净退出
        其他             => 报错退出（v0.1 不支持 MMIO/异常）
    }
}
```

## 错误处理

手写 `KvmError` 枚举（ioctl 失败 / 未知 exit / KVM 版本不符），实现 std::error::Error。
不引入 anyhow/thiserror。

## 测试

- 集成测试：跑二进制，断言 stdout 含 `hello from nanovm` 且退出码 0。
- CI：GitHub Actions ubuntu-latest（裸金属 runner 才有 KVM，普通 runner 用
  `KVM_RUN` 探测跳过）。

## 边界

本项目的边界就是“最小可运行的 KVM VM”，不做产品化演进。
